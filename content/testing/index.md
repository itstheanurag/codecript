Writing code that works once is easy. Writing code that continues to work after 100 other developers have touched the codebase over two years is incredibly difficult. That is why automated testing is a mandatory skill for senior engineers.

"How would you test this?" is a standard follow-up question for almost every architecture, API design, or algorithmic problem in a technical interview.

## What's Inside?

- **[The Testing Pyramid](./001-testing-pyramid)**: Understanding the balance between Unit, Integration, and End-to-End tests.
- **[Test-Driven Development (TDD)](./002-test-driven-development)**: The Red-Green-Refactor cycle and designing for testability.
- **[Mocking & Stubbing](./003-mocking-and-stubbing)**: Isolating dependencies and testing edge cases effectively.
- **[Load & Performance Testing](./004-load-and-performance-testing)**: Ensuring your system doesn't collapse under real-world traffic.
- **[Modern Test Runners](./005-modern-test-runners)**: The evolution from Jest to Vitest, and native tools like Bun.

> "Untested code is broken code."
