A **Minimum Spanning Tree (MST)** is a subset of edges in a weighted, undirected graph that connects all the vertices together, without any cycles, and with the minimum possible total edge weight.

---

## 1. The Intuition: "Minimum Material Cost"

Imagine you are an engineer tasked with connecting 10 different towns with electricity.
1. Every town must have power (every node must be connected).
2. You want to use as little cable as possible to save money (minimum total edge weight).
3. Any loop (cycle) in the power lines is a waste of cable.

An MST gives you the **cheapest possible way** to make sure everyone is "on the grid."

---

## 2. The Two Famous Strategies

### Kruskal’s Algorithm (The Edge Collector)
Kruskal’s is greedy and focuses on **Edges**.
1. Sort all edges from cheapest to most expensive.
2. Pick the cheapest edge. 
3. Does it create a loop? (Use **Union-Find** to check).
4. If NO, add it to your tree. If YES, throw it away.
5. Repeat until everyone is connected.

### Prim’s Algorithm (The Growth Strategy)
Prim’s is greedy and focuses on **Vertices**.
1. Pick one town to start. 
2. Look at all the cables you could use to connect a new town to your current "grid."
3. Pick the **cheapest cable** and add that town to the grid.
4. Repeat until every town is part of the grid.

---

## 3. Complexity Analysis

| Algorithm | Time Complexity | Space Complexity | Best for... |
| :------- | :-------------- | :--------------- | :---------- |
| **Kruskal's** | O(E log E)      | O(V + E)         | Sparse Graphs (few edges) |
| **Prim's**    | O(E log V)      | O(V + E)         | Dense Graphs (many edges) |

- `V` = Vertices, `E` = Edges.

## 5. Interview Pro-Tips

### When to Use Kruskal's vs. Prim's
- **Kruskal's**: Works on the edges directly. Better for **sparse graphs** (few edges). Uses Union-Find under the hood.
- **Prim's**: Grows the tree from a starting vertex. Better for **dense graphs** (many edges). Uses a Priority Queue under the hood.

In interviews, Kruskal's is almost always the expected answer because it's more intuitive and leverages Union-Find (which you've likely already covered).

### MST is a "Greedy" Algorithm
Both Kruskal's and Prim's are greedy — they always pick the cheapest available edge. It works here because adding the cheapest non-cycle edge can never hurt you: if there were a better solution, it would have to use a more expensive edge for the same connectivity, which is a contradiction.

### Classic Interview Problem: Connecting Cities with Minimum Cost
Given N cities and a list of possible cable connections with costs, find the minimum cost to connect all cities. This is exactly MST. Recognising that immediately and reaching for Kruskal's is what separates strong candidates.

### What Interviewers Are Testing
- Do you know both Kruskal's and Prim's at a high level?
- Can you implement Kruskal's using Union-Find?
- Do you know the time complexity and when each algorithm is preferred?
- Can you recognise the "minimum cost to connect everything" pattern?

---

## Key Takeaway

MST algorithms are essential for network design, circuit layouts, and cluster analysis in machine learning. They provide the **maximum connectivity for the minimum cost**.
